# مصفوفة جاهزية العمل دون إنترنت — جرد أولي

**تاريخ الجرد:** 12 نوفمبر 2026
**مرجع المصدر:** main عند 8e98aa350c999b2252cc8e3b5d2a8c6d0264b86b
**الحالة:** جرد أولي من تسجيل المسارات والملفات المعروفة؛ ليس اعتمادًا نهائيًا لكل مسار.

## حالات الإتاحة
- **مدمج:** يأتي مع التطبيق ولا يحتاج اتصالًا أو تنزيلًا منفصلًا.
- **حزمة Offline:** يجب تنزيل ملفات المسار صراحةً قبل فصل الإنترنت.
- **مخزن سابقًا:** متاح فقط إذا سبق تحميله والتحقق منه وما زال داخل سياسة الصلاحية.
- **انتهازي:** قد يبقى في cache محدود وقد يحذفه المتصفح.
- **شبكي:** يتطلب اتصالًا أو اعتمادًا/خدمة خارجية.
- **غير مدقق:** لم تُثبت جميع تبعيات المسار بعد.

## موارد مشتركة
| المورد | الموجود | المخاطر/العمل المتبقي |
|---|---|---|
| App shell | Service Worker + manifest + HTML fallback + ملفات JS/CSS الابتدائية | اختبار cold start/restart في وضع الطيران لكل متصفح مستهدف |
| Lazy chunks | Vite build manifest يجمع static dependency graph وallAssets | إثبات أن كل import ديناميكي وجميع ملفات route موجودة في الحزمة الناتجة |
| ملفات public | أضيف جرد recursive للملفات العامة المدعومة ودمجها في allAssets للحزمة الصريحة؛ sw.js مستثنى عمدًا | يجب التحقق من build output الفعلي ومن حجم الملفات العامة ومدى حاجة كل مسار لها |
| الخطوط | خط قرآني رسمي له محاولة pre-cache؛ Google Fonts تُخزن عند الطلب | قد لا تتوفر خطوط Google في أول فتح Offline؛ اختبار fallback وخيارات تضمين محلي مرخص |
| نص القرآن | بيانات محلية مجزأة ومتحقق منها | اختبار كل chunks وsearch indexes بعد package/restart |
| تفسير | cache بعد العرض وفق الخدمة الحالية | غير المحفوظ يحتاج الإنترنت؛ تحقق من freshness/expiry وسعة cache |
| أحاديث مرتبطة | cache بعد التحقق الصريح من الإسناد/المتن والدرجة | لا تعرض غير المخزن ولا تولد بديلًا |
| الصوت | 20 آية كحد للتخزين الانتهازي، cache بحد 40 عنصرًا؛ مصادر مقيدة | ليس مكتبة كاملة؛ تنزيلات pinned لم تنفذ بعد؛ EveryAyah stream-only |
| صفحات المصحف المصورة | cache منفصل محدود حتى 24 صفحة | ليس مصحفًا كاملًا Offline؛ تنزيل اختياري يحتاج حقوق/حجم/واجهة |
| Auth/Firebase/Firestore | خدمات سحابية | لا تعمل Offline؛ يجب أن تبقى القراءة/التقدم المحلي ممكنة دونها |
| APIs | /api مستثناة من cache العام | تبقى شبكية؛ لا تخزين لردود خاصة أو مفاتيح |

## فجوات مثبتة تحتاج تنفيذًا أو اختبارًا
1. Router الحالي يسجل المسارات عبر hash؛ يجب أن تغطي اختبارات الروابط العميقة كل المسارات وليس seerah فقط عند دمج PR الخاص بها.
2. أُضيفت ملفات public المدعومة إلى allAssets؛ ما زال يلزم التحقق من build output والـ fonts الخارجية وسياسة الأحجام.
3. تسجيل Service Worker يحدث بعد load في الإنتاج؛ يجب اختبار أول زيارة ثم reload ثم انقطاع الشبكة، وعدم افتراض أن الصفحة الأولى أصبحت controlled فورًا.
4. فحص حزمة Offline الحالية لا يثبت صلاحية كل ميزة؛ status الحالي يصف ملفات البناء التي دخلت manifest فقط.
5. لا يوجد في هذا الجرد إثبات حقيقي لتشغيل الهاتف في وضع الطيران بعد إغلاق التطبيق وإعادة تشغيله.
6. لا يوجد إثبات بعد أن كل العمليات المحلية تنجح أثناء انقطاع الإنترنت مع AuthGate أو أي تهيئة تعتمد على Firebase.
7. لا توجد بعد مكتبة تنزيل صوت كاملة؛ الخطة التفصيلية في OFFLINE_AUDIO_DOWNLOAD_PLAN.md.

### شروط اعتماد Offline فعليًا
1. تثبيت نظيف، تجهيز الحزمة أثناء الاتصال، إغلاق التطبيق/المتصفح بالكامل، تفعيل وضع الطيران، ثم إعادة الفتح من الأيقونة أو URL المحفوظ.
2. اختبار dashboard، إنشاء/تعديل/إكمال خطة، تحديث جلسة حفظ، مراجعة وتسجيل آية متعثرة، إنشاء اختبار، فتح المصحف، وقراءة التفسير المحلي دون أي طلب شبكة.
3. التأكد من حفظ التقدم بعد إغلاق التطبيق وإعادة فتحه، وأن فشل Firebase لا يمنع التغييرات المحلية ولا يكررها عند عودة الشبكة.
4. اختبار ملفات الصوت التي تم تنزيلها صراحةً بعد إغلاق التطبيق، وبيان واضح عند طلب صوت غير موجود محليًا. لا تعتبر cache الانتهازي تنزيلًا دائمًا.
5. اختبار مساحة تخزين منخفضة، انقطاع أثناء التنزيل، استكمال، ملف تالف، حذف/إخلاء cache، وتحديث Service Worker دون فقد البيانات المحلية.
6. تسجيل SHA الدقيق والمتصفح والجهاز ونظام التشغيل ونتيجة كل اختبار. لا تُستخدم عبارة «جاهز بالكامل دون إنترنت» قبل نجاح هذه الشروط.

## تصحيح مراجعة الصوت وملفات التطبيق — 2026-11-17

بعد إعادة فحص `main` مباشرة، تم تصحيح الجدول أعلاه: **إدارة تنزيل الصوت والتخزين المحلي والتشغيل المحلي ليست غائبة عن main**. الموجود بالفعل في main هو مدير تنزيلات من الإعدادات، IndexedDB jobs/files/jobItems، تخطيط التلاوات المعتمدة، quota preflight، عاملان كحد أقصى، Cache Storage بجيل/Generation، قراءة تحقق، حذف مرتبط بالمراجع، ومصدر تشغيل محلي ObjectURL قبل الشبكة. الفجوات الحالية هي قفل العامل على مستوى المهمة بين التبويبات، fallback عند غياب Web Locks، إيقاف العامل عند pause/cancel من تبويب آخر، durable staging، واكتشاف Cache keys اليتيمة بعد crash. PR #388 يعالج جزء القفل فقط، ولا يزال Draft.

كذلك، ملف `vite.config.ts` الحالي يبني manifest لملفات bundle (chunks/CSS/بعض الأصول المضمنة)، لكنه لا يستدعي بعد ماسح `public/` التكراري الموجود في فرع PR #366 القديم. لذلك لا نفترض أن كل ملفات المصحف/الأصول الثابتة العامة ضمن الحزمة الصريحة حتى يتم دمج هذه المعالجة واختبارها. Service Worker الحالي لا يحتوي بعد مهلة تنقل 6 ثوانٍ أو حدود cache التكيفية الموجودة في #366. PR #366 ما زال فرعًا قديمًا يحتاج port/rebase، وليس دليلًا على أن التغيير موجود في main.

**الحالة المصححة:** الصوت المحلي موجود كأساس عملي في main، لكنه ليس معتمدًا بالكامل حتى نجاح بوابات multi-tab/orphan/cold-restart. تجهيز ملفات التطبيق يحمّل ملفات bundle المعلنة، لكن تغطية كل public assets و604 صفحة المصحف دون زيارة مسبقة غير مثبتة حتى الآن.

## بوابة قبول الأجهزة الفعلية قبل إعلان الجاهزية — 2026-11-18

لا يكفي نجاح CI أو اختبار Playwright داخل جلسة متصفح واحدة. يجب تنفيذ السيناريو التالي على iPadOS Safari وAndroid Chrome، مع تسجيل إصدار المتصفح والجهاز وحجم الحزم:

1. **تهيئة أول اتصال:** فتح التطبيق كضيف، تجهيز حزمة التطبيق الأساسية، ثم التحقق من عدد الأصول المحفوظة وعدم وجود أخطاء تنزيل أو MIME.
2. **القرآن والحفظ محليًا:** إنشاء ثلاث خطط حفظ بتواريخ مختلفة، والتحقق من ظهور كل مهام اليوم والمتأخرة على الرئيسية، وبدء مهمة من خطة محددة ثم إكمالها؛ يجب تحديث الخطة الأصلية فقط.
3. **إغلاق بارد:** إغلاق المتصفح بالكامل/إزالة التطبيق من مبدّل التطبيقات، تفعيل وضع الطيران، ثم تشغيل WIRD من جديد. يجب أن يفتح التطبيق والبيانات المحلية دون طلب شبكة.
4. **المصحف النصي:** فتح السور والآيات والتنقل والبحث والإشارات المرجعية والحفظ والمراجعة دون اتصال، مع التأكد أن النص من بيانات WIRD المحلية.
5. **المصحف المصوّر:** تنزيل حزمة 604 صفحة، انتظار اكتمال الفحص، إغلاق بارد، ثم فتح صفحات متفرقة (1، وسط المصحف، 604) والانتقال بين الصفحات دون طلب خارجي. يجب أن يبقى العرض المرن المحلي متاحًا إذا غابت صورة أو فشل التحقق.
6. **التفسير:** تنزيل تفسير الميسر كاملًا (114 سورة)، إيقاف التنزيل في منتصفه ثم استكماله، إغلاق بارد، وقراءة التفسير دون شبكة. يجب ألا تُعرض سورة غير مكتملة باعتبارها جاهزة.
7. **الصوت:** تنزيل نطاق صوتي صغير ثم نطاق خطة حفظ، إيقاف/استكمال، تشغيل متصل بين الآيات، وإعادة تشغيل التطبيق في وضع الطيران. يجب أن يظل النص/التقدم محفوظين حتى لو فشل ملف صوتي.
8. **حدود التخزين:** اختبار مساحة كافية وغير كافية، فشل Cache Storage، رفض `persist()`, وحذف حزمة المصحف. يجب أن يفشل التنزيل غير الآمن برسالة مفهومة وألا تُحذف الملفات المكتملة.
9. **تحديث التطبيق:** بعد اكتمال التخزين، نشر Preview جديد في بيئة اختبار، التأكد من تحديث Service Worker دون كسر الحزم القديمة أو حذف بيانات المستخدم، ثم إعادة اختبار الإغلاق البارد.
10. **المزامنة:** التأكد أن وضع الضيف لا يحتاج شبكة، وأن تسجيل الدخول/المزامنة لا يغيّر البيانات المحلية أو يفعّل أعلام المزامنة غير المصرح بها.

**معيار النجاح:** لا توجد طلبات شبكة لازمة لمسارات العمل التي تم تنزيل محتواها؛ كل صفحة/ملف محلي يُتحقق منه قبل عرضه؛ الانقطاع لا يفسد البيانات ولا يعيد تنزيل المكتمل؛ وتظل وظائف القراءة النصية المحلية متاحة حتى عند فشل المحتوى الاختياري. لا يُعلن «كامل دون إنترنت» إذا بقي مصدر مطلوب غير منزّل أو لم ينجح اختبار الإغلاق البارد.
