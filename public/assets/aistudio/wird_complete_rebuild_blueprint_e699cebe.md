## 4. مواصفات نظام التصميم الفاخر (Premium Design System V2)

الهدف هو بناء هوية وقورة، هادئة، رفيعة المستوى تليق بمقام القرآن والعبادة، خالية من الزخارف العشوائية أو استعراض الـ UI الزائف.

### 4.1 لوحة الألوان المعتمدة (Chromatic Palette Tokens)

| العنصر (Token) | وضع الإضاءة (Light Mode) | الوضع الداكن (Dark Mode) | الدلالة البصرية والتطبيق |
| :--- | :--- | :--- | :--- |
| **Primary** | Deep Emerald (`#0F4C3A`) | Luminous Jade (`#1D775C`) | اللون السيادي، أزرار الإجراء الأساسية، العناوين الرئيسية. |
| **Background** | Warm Ivory (`#FAF8F5`) | Deep Charcoal Forest (`#121615`)| خلفية الصفحات المريحة للعين، بديل للأبيض الناصع المرهق. |
| **Surface** | Pure Crisp Pearl (`#FFFFFF`)| Muted Obsidian Surface (`#1A201E`)| بطاقات المهام، حاويات المصحف، القوائم المنبثقة. |
| **Accent** | Muted Champagne Gold (`#C8A355`)| Subtle Sand Gold (`#D4B26F`) | علامات الآيات المرجعية، نسب الإنجاز المتميزة، الإطارات. |
| **Borders** | Subtle Sandstone (`#E6E0D6`)| Deep Olive Slate (`#27302D`) | حدود دقيقة للغاية (1px)، فواصل هادئة غير مشتتة. |
| **Text Primary** | Deep Umber Black (`#1B1E1D`)| Soft Porcelain Gray (`#F3F5F4`)| نصوص الآيات، العناوين التعبدية، أرقام الورد. |
| **Text Muted** | Warm Slate Slate (`#65706B`)| Muted Moss Silver (`#9AA5A0`)| تفاصيل الترجمة، الهوامش، أوقات الصلاة الثانوية. |

### 4.2 القواعد التيبوغرافية وتجربة الخطوط (Arabic-First Editorial Typography)
1. **خط النص القرآني:** خط حفص بالرسم العثماني المعتمد، بأحجام ديناميكية قابلة للتعديل وسطور متسعة تمنع تداخل الحركات والإشارات.
2. **خط واجهات الاستخدام (Arabic UI):** خط عربي حديث فائق المقروئية (مثل: Noto Naskh Arabic / Readex Pro / Amiri للعناوين الجليلة).
3. **أرقام النصوص:** استخدام الأرقام العربية المشرقية داخل سياق الآيات، ودعم الأرقام القياسية في واجهات التوقيت والحسابات حسب تفضيل المستخدم.
4. **الحالات التفاعلية والحركة (Motion):** انتقالات ناعمة هادئة (200ms - 300ms Ease-Out)، بدون وميض مباغت، مع دعم إيقاف الحركة لمن يعانون من الحساسية البصرية (`prefers-reduced-motion`).

* **Phase 0: Baseline & Release Confidence:**
  - مراجعة وفحص آخر Merge commit وتحديد فروق التوافق مع PR #401 و PR #403.

* **Phase 5: Architecture Refactoring:**

  - مراجعة مؤشرات الأداء (Lighthouse Score >= 95, Bundle Size Budget).

## 6. ميثاق الثوابت والضوابط الصارمة غير القابلة للمساس (Inviolable Constraints)

| النطاق / المحرك | الشرط الهندسي الصارم الذي يُمنع المساس به |
| :--- | :--- |
| **القرآن الكريم** | النص المحلي الموثوق بالرسم العثماني المعتمد هو المصدر الأوحد. **يُحظر منعاً باتاً** توليد أي آيات أو أحاديث أو أحكام بالذكاء الاصطناعي، ويتم التحقق من النزاهة التشفيرية لقاعدة البيانات عبر Checksum. |
| **المصحف الشريف** | الالتزام بطبعة الـ 604 صفحات المعتمدة، مع صيانة دقيقة لإحداثيات الآيات، علامات الأجزاء والأحزاب، ونقاط التوقف والعلامات المرجعية. |
| **الحفظ والمراجعة** | الحفاظ المطلق على خطط المستخدم الحالية، سجلات جلسات الإتقان، وعدم تصفير درجات التكرار عند تحديث الواجهات. |
| **وضع الضيف (Guest)** | تشغيل التطبيق بالكامل بدون إجبار المستخدم على التسجيل، وحفظ كل الورد والخطط محلياً في `IndexedDB`. |
| **المصادقة (Firebase Auth)** | صيانة تجربة تسجيل الدخول السلسة بالبريد و Google OAuth مع الاحتفاظ بمعرفات المستخدمين كما هي. |
| **قواعد Firestore** | عدم التعديل على Security Rules التي تحمي خصوصية مستخدمي الحسابات أو تغيير هياكل الوثائق دون نصوص ترحيل متوافقة مع الإصدارات السابقة (Backward Compatibility). |
| **المزامنة (Sync Engine)** | صيانة آليات منع تضارب البيانات وحظر إحياء العناصر المحذوفة (Anti-resurrection logic) عبر التزامن غير المتصل. |
| **التخزين دون إنترنت** | الحفاظ على إمكانية القراءة، تصفح الأذكار، استعراض المواقيت المحفوظة، وتشغيل التلاوات المحملة محلياً دون أي اتصال شبكي. |
| **التكنولوجيا الأساسية** | **يُمنع استبدال React / Vite بـ Next.js**، ويُمنع إقحام خدمات سحابية مدفوعة ترهق تكلفة التشغيل، ويُمنع العبث بمتغيرات بيئة الإنتاج على Vercel أو مفاتيح المزامنة. |
